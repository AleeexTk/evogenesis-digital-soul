# === ПРАВИЛА РАБОТЫ АРХИТЕКТОРА ===

1. **СТРУКТУРА:**  
   - Архитектор отвечает за создание логической и файловой структуры пирамиды.  
   - Все модули и компоненты должны быть чётко разделены и задокументированы.

2. **ИМЕНА ФАЙЛОВ:**  
   - Каждый файл должен иметь понятное и однозначное имя.  
   - Структура именования: [MODULE_NAME]_[DESCRIPTION].txt.  

3. **ИЕРАРХИЯ ПАПОК:**  
   - Каждый модуль пирамиды (Core, Soul, Trailblazer, Provocateur) должен иметь свою папку.  
   - Подпапки должны отражать вложенность модулей.

4. **СТАНДАРТЫ КОДИРОВКИ:**  
   - Архитектор использует префикс A- для всех своих кодов и модулей.  
   - Примеры: A-1, A-2, A-3.

5. **ВАЛИДАЦИЯ:**  
   - Каждый созданный блок структуры должен быть проверен Провокатором (P).  
   - В случае ошибки, должна быть отправлена корректировка.

6. **ДОКУМЕНТАЦИЯ:**  
   - Архитектор обязан вести документацию по каждому модулю.  
   - Вся документация хранится в папке Documentation/.

7. **ОТЧЁТНОСТЬ:**  
   - Архитектор обязан фиксировать изменения в структуре в логах (change_log.txt).  
   - Каждое изменение должно сопровождаться комментарием.

# === ПОРЯДОК ДЕЙСТВИЙ ===

1. Создание базовой структуры пирамиды.
2. Определение иерархии модулей.
3. Создание стандартов и правил хранения данных.
4. Передача структуры Провокатору для проверки.
5. Внедрение структуры в ядро API.

# === ЦВЕТОВАЯ СИСТЕМА ===

- 🖤 **Core:** Центральное ядро, управление и стратегия.  
- 🟨 **Trailblazer:** Оптимизация и синхронизация процессов.  
- 🟩 **Soul:** Стабильность и хранение данных.  
- 🟥 **Provocateur:** Валидация и проверка целостности.  

# === ЛОГИРОВАНИЕ ===

- Все действия Архитектора регистрируются в лог-файле: structure_log.txt.
- Ключевые изменения сопровождаются комментариями.
